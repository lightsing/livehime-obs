Architecture

开播状态机、协议对齐与安全隔离

当前版本沿用 v0.2.4 对直播姬 8.15.0.11311 的协议适配，并在客户端会话、网络通道与 OBS 宿主运行库三个层面实施隔离。

01 · 会话与设备隔离

WebView2 InPrivate + DPAPI

扫码登录使用独立 InPrivate profile，不读取直播姬或系统浏览器数据。Cookie 经 Windows 当前用户 DPAPI 加密存入 session.dpapi，与持久化 device-id 分离处理。

02 · 协议与签名对齐

8.15.0.11311 与 traceid

身份校验与直播请求按各自签名合同分离（appkey/platform/ts 与直播参数），开播请求携带独立生成的 UUIDv4 + 毫秒时间 client_traceid 请求头。

03 · 控件与输出桥接

进程内临时 RTMP 服务

NativeStreamControls 接管 OBS「控件」按钮信号；开播时通过 ObsBridge 注入临时单路 RTMP 服务（仅驻留进程内存、不调用写盘接口），下播后恢复原服务。

04 · 实时与 TLS 隔离

Goim 单连接与私有后端

直播互动、礼物流水、房间观众与大航海共用一条 Goim TCP 长连接（静态链接 zlib 1.4 / Brotli 1.2.1，支持 Protobuf V2 礼物与 4 类超管广播）。私有 qschannelbackend.dll 放于插件目录，不覆盖宿主 Qt。

网络与隐私边界

  • 分区列表、封面预览图和观众远程头像经无 Cookie 的限流匿名通道请求，不向图片 CDN 发送账号 Cookie 或设备标识。
  • 匿名/神秘人身份（含嵌套 uinfo/user_info 与 is_mystery 字段）在展示前统一脱敏为「神秘用户」。
  • 互动浮窗使用 WS_EX_TRANSPARENT 穿透鼠标点击。输入框和发送按钮放在按可见区域裁剪的独立窗口内。停靠、隐藏、关闭或重启后恢复正常输入。
  • 日志与测试脱敏输出不打印 Cookie、请求体或推流密钥。

安装器布局与升级策略

  • 现代独立目录（默认）：C:\ProgramData\obs-studio\plugins\livehime-obs（根部 DLL、data/ 资源、installer/ 卸载器）。
  • 兼容旧根目录布局：支持继续识别并原位升级早期 0.2 obs-plugins\64bit 布局，保留原安装范围与同一份卸载日志。
  • 安装器先核验 OBS 安装目录内的 obs64.exe（33.0.1 x64 / Qt 6.11.1）并检测目标目录进程占用。
  • 卸载仅清除已登记载荷，保留 OBS 场景、配置、其他插件与用户登录缓存；安装包未做 Authenticode 签名，旁附 .sha256 与 .json。
Codebase

源码模块划分

插件核心位于 src/，每个模块职责边界清晰，支持不依赖真实网络和真实 OBS 输出的离线回归测试。

protocol.* & bili-client.*

负责精确参数编码、排序、签名向量校验、独立 Cookie 容器、异步 HTTPS 超时控制、封面直传与房间状态保存。

login-dialog.* & session-store.*

托管 WebView2 扫码页面与 Cookie 导入，使用当前 Windows 用户 DPAPI 加密持久化会话并维护独立设备标识。

live-controller.* & obs-bridge.*

管理账号/房间/开停播状态机、标题防抖队列、封面排队上传、异步 epoch 隔离，以及临时 RTMP 服务注入与恢复。

native-stream-controls.* & room-dock.*

对接 OBS 33.0.1 Qt 控件按钮及延迟推流入口信号；提供 B 站直播主面板（含父子双下拉联动与搜索、封面悬停入口）。

room-realtime.* & goim-* & gift-v2.*

维护单连接 Goim TCP 分帧、zlib/Brotli 解压、心跳重连、JSON/Protobuf V2 礼物解析以及观众/大航海榜单节流刷新。

floating-windows.* & moderation-* & cover-crop-dialog.*

注册稳定 ID 的原生 QDockWidget 面板、处理 4 类超管广播弹窗与告警音，以及本地 4:3 封面拖动/缩放裁切导出。

Build from Source

从源码构建与打包

需要 Visual Studio 2022（C++ 桌面开发组件）、Windows SDK、CMake 3.28+、PowerShell 7 与本机 OBS Studio 33.0.1 x64。

一键构建、校验与打包命令

build.ps1 会依据 deps/dependencies.lock.json 与 deps/goim-codecs.lock.json 下载并校验 SHA-256 锁定依赖（OBS 头文件、Qt 6.11.1 开发包、WebView2 SDK、zlib 1.4 与 Brotli 1.2.1 源码），从本机 OBS DLL 导出表生成导入库，无需重编完整 OBS。

PowerShell 7 · Windows x64 
git clone https://github.com/lightsing/livehime-obs.git
Set-Location livehime-obs
.\scripts\build.ps1
.\scripts\verify-load.ps1
.\scripts\package.ps1
.\scripts\build-installer.ps1

复用本地依赖缓存与安装器验证

已下载依赖可通过 -DependenciesRoot 与 -SkipBootstrap 复用；安装器测试脚本会创建合成的 OBS 宿主目录与独立测试 GUID，验证安装、升级、版本拒绝、忙碌保护与卸载流程，不改动真实 OBS。

PowerShell 7 · 离线测试与缓存复用 
.\scripts\build.ps1 -DependenciesRoot D:\path\to\deps -SkipBootstrap
ctest --test-dir build -C RelWithDebInfo --output-on-failure
.\scripts\test-installer.ps1 -InstallerPath dist\livehime-obs-0.4.4-windows-x64-setup.exe
Verification

自动化验证覆盖范围

GitHub Actions（.github/workflows/windows.yml）在每次推送与发布 Tag 时执行完整构建、16 项 CTest 测试、DLL 加载核验与安装器矩阵测试。

离线 CTest 套件（16 项）

  • protocol-vectors：转义排序签名向量、client_traceid、Cookie 范围与 RTMP 选择。
  • session-store-roundtrip：当前用户 DPAPI 加解密、损坏缓存拒绝与设备标识持久性。
  • controller-state-transitions & obs-bridge-lifecycle：标题/封面并发保存、开停播时序、重连与异常回滚。
  • ui-crop-smoke & native-stream-controls：4:3 裁切、双下拉搜索、原生按钮及延迟推流信号接管。
  • goim-codec-and-tcp、gift-v2-wire-parser、realtime-state-isolation & realtime-floating-windows：TCP 分帧解压、Protobuf V2、停靠/穿透与超管弹窗。
  • 自动更新测试覆盖 npm 签名、下载与缓存、更新偏好，以及所有 OBS 实例退出后再安装。
  • danmaku-emotes 检查独立和混排表情、重复标签以及缺失或无效的图片地址。

离线验收的已知边界

  • 离线测试使用合成请求向量与替身后端，不登录真实账号、不修改真实房间、不执行真实推流。
  • GitHub Release 附件同步提供匹配的 Qt Base 源码包、OBS 依赖构建配方、校验和及 CI 生成的 validation.json 报告。
  • 真实扫码确认、平台下发开播授权、音频/视频长期推流稳定性以及真实超管通知仍以实播验证为准。
